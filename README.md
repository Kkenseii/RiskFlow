# RiskFlow — учебный MVP оркестратора

## Что демонстрирует
- единая очередь ручных и регламентных запусков;
- атомарный захват ресурсов процесса/даты и всех источников данных задачи;
- идемпотентность по процессу, дате и нормализованному набору источников;
- журнал событий и просмотр активных блокировок;
- проверка даты и освобождение устаревших блокировок при старте (TTL);
- параллельное выполнение независимых задач;
- последовательное выполнение задач, использующих общий источник;
- хранение истории и статусов в SQLite.

## Запуск
1. Установить Python 3.10 или новее.
2. В терминале перейти в папку проекта.
3. Создать виртуальное окружение (необязательно, но рекомендуется):
   `python -m venv .venv`
4. Активировать окружение:
   Windows: `.venv\\Scripts\\activate`
   macOS/Linux: `source .venv/bin/activate`
5. Установить зависимости: `pip install -r requirements.txt`
6. Запустить интерфейс: `streamlit run app.py`

## Тесты
`python -m unittest -v`

## Архитектурное решение
SQLite используется как единая точка координации. Захват ресурсов выполняется внутри
транзакции `BEGIN IMMEDIATE`: задача получает все нужные ресурсы целиком либо не получает
ничего. Список ресурсов сортируется, что задаёт единый порядок захвата и исключает
классическую циклическую взаимоблокировку при поэтапном захвате.

## Ограничения учебной версии
Это демонстрационный прототип для одного процесса приложения и одной SQLite-базы.
Для промышленной многосерверной системы понадобятся серверная СУБД, распределённые
блокировки/аренды с обновляемым TTL, полноценное восстановление зависших задач,
авторизация и интеграция с реальными ETL/риск-алгоритмами. В текущем MVP восстановление
по TTL выполняется при инициализации оркестратора; SQLite не заменяет распределённый
координатор для нескольких серверов.
